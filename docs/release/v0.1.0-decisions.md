# v0.1.0 implementation decisions

Decisions made while executing the approved plan, in chronological order.
Each records the trade-off or consequence if the judgment is wrong.

- Headerless standard files cannot reliably identify a wrong caller-supplied metric/dimension when layouts overlap — validate all detectable structure and document this intrinsic limit — cost if wrong: users need external metric/dimension metadata.
- Generated specialization is conditional in the spec; start with generic shared storage and concrete metric wrappers, and generate only when profiling proves dispatch costs — reduces maintenance and footprint — cost if wrong: later specialization refactor.
- Continue all authorized implementation/PR work without another confirmation; commits remain on the implementation branch until verified — user explicitly commenced the approved plan.
- omit tests of inert constants/getters; exercise their consumer behavior instead, per writing-good-tests — cost if wrong: a constant error is caught by integration rather than a redundant value assertion.
- consolidate byte codecs into internal/codec with a small metric enum and exact layout values, rather than duplicating identical byte accessors across five packages — no dispatch inside vector kernels; reduces maintenance — cost if wrong: specialization can later split codecs without public changes.
- Hamming uses upstream bit-coordinate splitting, not two-means (spec terminology was inaccurate) — pinned C++ source is the compatibility authority — cost if wrong: split topology/recall divergence, covered by golden and cross-language tests.
- byte identity excludes only C++-uninitialized split fields/padding (dot norm/built/padding; Hamming padding/unused words) — literal identity would require reproducing undefined stack bytes; Go output zeros them — cost if wrong: byte comparisons must canonicalize those fields. Angular/Euclidean/Manhattan raw bytes match exactly.
- OnDisk construction is serial and retains builder input vectors in memory; tree-node storage is file-backed — one writer owns remapping and no shared writable mmap state — cost if wrong: less parallel build throughput for OnDisk workloads. Portable non-mmap targets use the memory fallback.
- port useful legacy scenarios into the five-metric public API, small/sparse, lifecycle, C++ fixture, math, and benchmark suites; remove old architecture/tests together — retaining imports of removed packages prevents module cleanup — cost if wrong: a missed scenario is a regression risk, addressed by final review and coverage.
- use skill slug goannoy-v01-upgrade rather than a dotted folder — skill metadata allows lowercase letters/digits/hyphens — cost if wrong: documentation links need one rename.
- validate actual workflow syntax and execute its commands rather than adding a test that greps documented command strings — writing-good-tests prohibits change-detector tests and text presence proves no behavior — cost if wrong: documentation/CI command drift relies on review.
- restrict Hamming dimensions to2²⁴ rather than revise public Result type — guarantees exact count/order under the approved float32 contract — cost if wrong: larger otherwise-standard Hamming files are unsupported.
- reject float vectors with overflowing float32 squared norm and error on derived non-finite distances — avoids NaN heap ordering while retaining ordinary C++ arithmetic — cost if wrong: some finite input ranges require application scaling.
- zero-valued opaque public handles remain unsupported, use constructors/Open — README states that ownership contract — cost if wrong: zero-value misuse can panic.
- external mutation/truncation of mapped files remains unsupported — storage ownership is explicitly documented — cost if wrong: outside writers can fault mappings.
- headerless wrong-metric/dimension overlap still needs external provenance — no intrinsic discriminator exists — cost if wrong: a structurally valid wrong layout may be accepted.
- literal uninitialized C++ padding remains excluded — only defined bytes have reproducible meaning — cost if wrong: whole-file byte comparisons require canonicalization.
- preserve upstream angular self-distance anomalies at very large finite magnitudes — compatibility includes float32 norm-product overflow; NaN-producing unsupported ranges now return errors — cost if wrong: applications should scale/normalize unusually large angular vectors.
- native platforms unavailable locally are verified by CI, not claimed as local execution — cross-compilation alone is insufficient — cost if wrong: environments outside the CI matrix remain unexecuted.
- physical power-loss durability is bounded by OS sync/rename guarantees; no new fault-injection framework added — existing callback/sync/close tests and publication regression cover reproducible failures — cost if wrong: hardware/OS failure behavior is not physically demonstrated.
