# v0.1.0 release evidence

This is a breaking **pre-1.0** Go API release, not v1.0.0. Module path remains
`github.com/mariotoffia/goannoy`. No tag, release publication, or merge is part
of implementation verification.

## Implemented scope

- Five concrete metric packages: angular, dot, Euclidean, Manhattan, Hamming.
- Fluent configuration, checked boundaries, immutable indexes, reusable searchers.
- Standard signed32/float32 little-endian files and packed uint64 Hamming.
- Exact defined serial C++ fields; deterministic parallel Go construction.
- Read-only mmap / owned-memory fallback, transactional output, serial OnDisk.
- Stable NEON/SSE2, scalar fallback, isolated experimental AMD64 Go SIMD.
- Standard-library-only runtime; per-metric linker isolation.
- Source-shape-based [upgrade skill](../../skills/goannoy-v01-upgrade/SKILL.md).

## Release limitations

- Headerless files cannot prove metric/dimension provenance; callers retain it.
- C++-uninitialized split padding is zeroed, not reproduced. Fixture hashes use
  that same explicit canonicalization; all defined fields still come from C++.
- Parallel topology is repeatable for fixed settings, not identical to C++ threading.
- OnDisk builds are serial and retain input vectors in memory.
- Float64/custom-policy/legacy Hamming consumers need explicit migration choices.
- External file truncation while mapped is unsupported.
- Hamming is limited to2²⁴ bits for exact float32 counts. Float inputs need a
  finite float32 squared norm; derived non-finite distances return an error.
  Upstream angular rounding at unusually large magnitudes is retained.
- Windows and other fallback platforms use owned memory; rename atomicity is
  platform-dependent. A directory-sync error can occur after the new file commits.
- Cross-compilation does not count as executing another architecture's assembly.
