# Spotify Annoy compatibility

Fixtures are generated by Spotify Annoy commit
`379f744667aba6b40ba3db8a07678df173a88f74`, never by GoAnnoy.
They use 64 items, three trees, seed 42, one build thread, float32/int32,
and three uint64 words for the 130-bit Hamming fixture.

Regenerate from this directory:

```sh
ANNOY_SOURCE=/absolute/path/to/pinned/annoy go generate
```

The generator verifies the source commit and compiles with:

```sh
c++ -std=c++17 -O2 -ffp-contract=off -fno-tree-vectorize \
  -I"$ANNOY_SOURCE/src" cpp/generate.cc -o /tmp/annoy-fixtures.out
```

The C++ executable has two modes: `write DIRECTORY` builds fixtures and
`read DIRECTORY` independently loads and queries saved files. Both emit
JSON query expectations. The Go generator records SHA-256 digests.
Before hashing it zeros only C++-uninitialized dot/Hamming split fields and
padding. All defined fields and query expectations still come from C++;
canonicalization is necessary for reproducible files rather than stack garbage.
Normal tests require the committed fixtures and do not require C++.

Run the explicit Go -> C++ release gate from the repository root:

```sh
ANNOY_SOURCE=/absolute/path/to/pinned/annoy go test -tags cppcompat ./compat -v
```

That gate builds the C++ reader and queries Go-built files for every metric in
both serial and parallel modes. Missing C++ tools or source fail the gate.
